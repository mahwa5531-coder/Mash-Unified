# Cleanup Report — 2026-10-05

**Mandate:** the cloud layer keeps ONLY user-related code (Google-OAuth
identity, subscriptions/quotas, payments) and the LLM tunnel (rate limit →
SSE → Bifrost). The entire agent runtime moves to the desktop; only LLM-call
metering is stored. Auth is Google OAuth ONLY — no email/password, no
signup/recovery, no other provider.

**Result (measured from git):** production Go **18,217 → 11,852 lines**
(81 → 62 files, −35%); test code 20,607 → 5,992 lines (the fault-injection
validation suite for deleted machinery was replaced by focused suites).
36 routes → 22. 17 tables → 12. Build, vet and the full test suite (including
`-race`) pass.

## 5. Migration ⚠️

The migration chain is **renumbered from scratch** (000001–000007): the
schema is the source of truth for a clean v1. An existing database that ran
the OLD chain cannot be migrated in place — the old
`agent_sessions`/`agent_runs`/`usage_records`/`auth_recovery_tokens` tables
and `users.password_hash`/`email_verified`-for-local semantics have no
successor state.

**Action for the dev Aiven database (pre-launch, no user data at risk):**

```sql
-- psql "$NEXAU_DATABASE_URL"
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
```

then restart the API — the fresh chain applies on boot. Existing Google
users will re-provision on their next sign-in (identity re-anchors on the
Google `sub` automatically).

## 7. Known trade-offs (deliberate)

1. **No Idempotency-Key on LLM calls** — matches OpenAI semantics; the
   desktop owns retry policy. A retried request that already reached Bifrost
   may double-count usage.
2. **Quota gate fails open** on a usage-store error (availability posture;
   the quota is a plan-abuse bound, not a security boundary).
3. **Concurrency slots are Redis-only** with a TTL backstop (no PG
   reconciliation anymore — there is no running-calls table by design).
4. **Non-stream responses are re-marshaled** from the decoded upstream body
   (the raw bytes were not retained by the client; the Extras map carries
   unknown fields verbatim).

## 8. r3 (2026-10-05, later): rolling windows + dynamic normalization

The monthly-quota model is replaced by the two-window model, and token
accounting becomes table-driven. Both changes are pure SQL state —
operators change behavior with `UPDATE`, no restart.

**Quota model**: `plans.limits.monthly_token_quota` is retired;
`window_5h_tokens` (rolling 5-hour burst budget) and `window_weekly_tokens`
(rolling 7-day weekly budget) replace it. The gate (`llm.Proxy.admit`)
checks both windows via one indexed SUM per request
(`repos.WindowUsage`) and rejects with `WINDOW_QUOTA_EXCEEDED` (429)
carrying `window`, `quota_tokens`, `used_tokens` and the exact `resets_at`
(`repos.WindowRecovery`: the earliest instant the rolling sum drops back
below quota). `/v1/me` renders the same numbers (windows array, percent,
`resets_at` when binding). See `docs/TABLES.md` for the seeded budgets.

**Token accounting**: new `token_normalization` table (migration 000008) —
per-model weights (`input_weight`, `cached_read_weight`,
`cached_write_weight`, `output_weight`; exact key > `provider/*` pattern >
`'*'` default). Metering applies the resolved rule and stores BOTH the
normalized values and the raw provider numbers (`llm_calls.raw_prompt_tokens`,
`raw_completion_tokens`). The API caches rules for
`NEXAU_NORM_CACHE_TTL` (default 30s, stale-on-error with backoff), so an
`UPDATE` takes effect within ~30s.

**Migration 000008** also converts monthly-era `plans.limits` rows to the
window keys (idempotent; fresh installs already converge via the 000007
seed). Existing databases upgrade in place — no re-provisioning needed for
r2→r3; r1 (pre-cleanup) databases still re-provision per §5.

**Files**: `internal/llm/norm.go` (RuleCache), `internal/llm/proxy.go`
(window gates, weight-driven NormalizeUsage), `internal/store/repos/usage.go`
